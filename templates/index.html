What the validator checks

Syntax

  • The text is non-empty and within the size limit.
  • The text parses with Python's json module.
  • Parse errors report the line, column, and reason.

Schema

  • The root value is a JSON object.
  • All five required keys exist and no extra keys are present.
  • Each scalar field is a string or null; empty strings and "N/A" are rejected.
  • The date is a real ISO YYYY-MM-DD calendar date or null.
  • Topics is an array containing only non-empty strings.
  • The output can be serialised back to valid JSON.

Viva-ready explanations. Short, exam-friendly notes on prompt engineering, context engineering, structured output, missing information, and validation.

Core concepts

What is prompt engineering?

Prompt engineering is the practice of writing instructions for an AI system so that its response is accurate, relevant, and usable. A good prompt states the task, the input, the constraints, and the required output format. It removes ambiguity before the model answers.

What is structured-output prompting?

Structured-output prompting asks for a response in a fixed machine-readable format, such as a JSON object with named fields. Instead of free text, the system receives predictable keys that software can parse, validate, store, and display. This is the difference between "tell me about the workshop" and "return exactly these five fields as JSON".

How does context engineering help?

Context engineering is deciding what information and instructions the system should see. Here, the context is the source paragraph plus the output schema, the evidence rule ("extract only stated facts"), and the missing-information policy. Supplying the right context is often more important than changing the wording of the question.

Why predefined JSON fields?

Fixed fields make the output comparable across paragraphs. Every record has the same shape, so a table, a database, or a test suite can rely on title, date, venue, speaker, and topics always being present. It also makes automated validation possible.

Why should missing information be null?

null means "this value is not available". An empty string or the text "Unknown" is ambiguous: it could be real data, a placeholder, or a parsing bug. JSON null is a distinct type that validation can check, and it prevents a missing value from being mistaken for a real one.

JSON syntax vs schema validation

Syntax validation checks whether the text is well-formed JSON — braces, quotes, commas, and types must parse. Schema validation checks whether the parsed object follows the agreed structure: correct keys, correct types, and valid values. A document can parse perfectly and still fail the schema. This project reports both separately and never treats parsing alone as success.

How is hallucination reduced?

Hallucination is invented information presented as fact. This project reduces it with three layers: an evidence-only prompt rule, a deterministic engine that can only emit values found by explicit patterns, and a validator that rejects malformed or unsupported structure. The engine also records evidence for each field, so a value can be traced back to the paragraph.

Limitations of rule-based extraction

Rules are predictable and free to run, but they are limited to the patterns they encode. Unusual phrasing, indirect statements, and implicit facts may be missed. This is a deliberate trade-off: the system prefers a null over a guess. A production system could combine rules with a validated language-model adapter, keeping the same schema and validation layer.

Prompt anatomy

  1. Role — "information-extraction component".
  2. Task — convert the paragraph into one JSON object.
  3. Evidence rule — extract only explicitly supported facts.
  4. Schema — five named fields with types.
  5. Missing-data policy — null / empty array.
  6. Output constraint — JSON only, no fences or commentary.
