1. Experiment Title

Prompt-Based Information Extraction System: structured prompt design, deterministic extraction, and JSON schema validation.

2. Aim

To design a structured prompt and build a web application that converts an unstructured workshop paragraph into a validated five-field JSON object, correctly representing missing information as null or [].

3. Objectives

  1. Design two structured prompts: Standard Extraction and Missing-Information-Safe Extraction.
  2. Implement a deterministic extraction engine that needs no external AI API key.
  3. Produce a JSON object with exactly five fields: title, date, venue, speaker, topics.
  4. Represent missing scalar values as null and missing topics as [].
  5. Validate JSON syntax and schema independently with clear error messages.
  6. Test complete, incomplete, and sparse paragraphs and report actual results.
  7. Document the work and prepare it for GitHub publication and deployment.

4. Problem Statement

Workshop announcements are written as free-form prose. The same facts appear in different orders and phrasings, and some facts are often missing. Extracting those facts manually is slow and inconsistent. A naive extractor may invent a venue or convert "next month" into a false calendar date. The problem is to extract only supported facts and to represent everything else honestly.

6. Theory

Prompt engineering is the discipline of writing precise instructions for an AI system. A structured prompt defines the role, the task, the evidence rule, the output schema, and the policy for missing data.

Context engineering is selecting the information supplied to the system. Here the context is the paragraph, the five-field schema, and the rule "extract only explicitly supported information".

Structured output means returning machine-readable JSON with fixed keys rather than free text. This makes the result testable and storable.

Missing information is represented with JSON null (and [] for topics). This distinguishes "not available" from an empty or invented value.

Validation has two layers. Syntax validation checks that the text parses as JSON. Schema validation checks keys, types, date format, and topic contents. Passing one does not imply passing the other.

Important distinction: the prompts in this project are structured specifications. The default extraction is performed by a deterministic rule-based Python engine, not by a language model. The application does not claim that a model executed the prompt.

7. Algorithm

  1. Accept the paragraph and the selected prompt mode.
  2. Reject empty input, over-length input, or an unsupported mode with a clear error.
  3. Normalise whitespace and typographic characters.
  4. Split the paragraph into sentences, protecting abbreviations such as "Dr.".
  5. Extract the date with ordered patterns (ISO, day-month-year, month-day-year). Reject invalid, partial, relative, and ambiguous dates.
  6. Extract the title using verb patterns and a sentence-level event phrase. Apply documented specificity rules for the selected mode.
  7. Extract the venue only from explicit venue phrases. Optionally qualify it with an explicitly stated host institution and city.
  8. Extract the speaker only from a named-person pattern. Reject role-only and "not announced" references.
  9. Extract topics after an explicit cue such as "will cover" or "topics include", splitting on commas and "and".
  10. Build the five-field object with null / [] for absent values.
  11. Validate syntax, then validate the schema, then return the result with evidence and notes.

10. Structured Prompt

The Standard Extraction prompt contains nine explicit instructions, the output schema, field rules, and the source paragraph. See the Prompt Lab tab for both full prompts and a readable comparison.

You are an information-extraction component. Your only task is to convert the SOURCE PARAGRAPH below into one JSON object that follows the OUTPUT SCHEMA.

INSTRUCTIONS
1. Read the supplied paragraph carefully before extracting anything.
2. Extract only information that is explicitly supported by the paragraph.
3. Identify the workshop title, date, venue, speaker, and topics.
4. Return a JSON object with exactly these predefined field names: title, date, venue, speaker, topics.
5. Represent every missing or unavailable scalar value as null.
6. Represent topics as an array of strings.
7. Never invent details, infer a speaker, or fill gaps using assumptions.
8. Return JSON only, without Markdown code fences or explanatory text.
9. Follow the defined output schema exactly. Do not add extra keys.

OUTPUT SCHEMA
{ "title": string | null, "date": "YYYY-MM-DD" | null, "venue": string | null,
  "speaker": string | null, "topics": [string] }

SOURCE PARAGRAPH
"{{ '{{PARAGRAPH}}' }}"

Return the JSON object now.

12. Missing-Information Handling

For the paragraph "The college will conduct a Python programming workshop on 20 December 2026. Students will learn file handling and exception handling.", the venue and speaker are not stated. The engine returns null for both. It does not turn "the college" into a venue, and it does not invent a speaker. For "A technical workshop will be organized next month. The speaker has not been announced.", the relative date, generic title, venue, speaker, and topics all remain null / empty.

17. Limitations

  • Rule-based extraction covers common announcement patterns, not arbitrary language.
  • Indirect or implicit statements may produce null even when a human could infer the value.
  • The engine does not resolve relative dates such as "next month" by design.
  • No database is used; each request is processed in memory.
  • No authentication is included, because the application is a single-user practical demonstration.

18. Future Scope

  • Add an optional, environment-configured LLM adapter with independent response validation.
  • Support multiple event types and additional schema fields.
  • Export records to CSV or a database.
  • Add multi-paragraph batch extraction.
  • Add confidence calibration and a reviewer approval step.

19. Conclusion

The experiment demonstrates that a well-specified structured prompt and a transparent deterministic engine can produce reliable, schema-valid JSON from unstructured text. Representing missing values as null and separating syntax validation from schema validation makes the output honest and testable.

20. Viva Questions with Answers

QuestionAnswer
What is prompt engineering?Writing precise instructions that define the task, context, constraints, and output format for an AI system.
What is structured-output prompting?Asking for a fixed machine-readable format, such as JSON with named fields, instead of free text.
Why use JSON?It is language-independent, easy to parse, and easy to validate.
Why use null instead of "N/A"?null is a distinct JSON type meaning "no value". "N/A" is a string that could be mistaken for real data.
Difference between syntax and schema validation?Syntax checks that the text parses as JSON. Schema checks that the parsed object has the required keys, types, and value formats.
Does this project use an LLM?No. The default engine is deterministic and rule-based. The prompt is a specification. An optional LLM adapter is not enabled.
How is hallucination reduced?Evidence-only rules, explicit pattern matching, null defaults, and independent validation.
Why is "next month" returned as null?It is relative and has no unambiguous calendar date. Converting it would invent information.
What is context engineering?Deciding what information and instructions to provide so the system has exactly the relevant context.
Why keep the schema fixed?Comparability, testability, and predictable downstream processing.
